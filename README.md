# 周转箱内衬规格归并

从必需适配特征归并规格，追溯卡住共用方案的组合，并核算未测特征补全后指定打样组能否共用。

澄浦装配包装组为两座工厂的三条装配线维护循环周转箱及可替换内衬。 包装工程师从工装台账提取工位必需的箱体接口、支撑位及让位特征，过去按箱型在表格里人工配对。规格管理员导入待归并内衬（两厂尚未测完的特征以问号标注并保留），复核员核对切树结果、超线组合与未测项补全结论，采购员据签核清单安排打样和备料。

- 同箱型的内衬可能有不同支撑或让位要求，单看箱体尺寸容易误判共用。
- 中间规格与两端分别相近时，逐对手工合并容易把差异过大的两端塞进同一组。
- 两厂交来的特征还有未测项，采购无法判断指定打样组补测后是否仍能共用。
- 采购收到组名单后还要反查具体冲突，打样前很难定位要验证的部位。

## 业务模块

| 模块 | 用途 |
|---|---|
| 内衬归并总览 | 查阅业务口径、当班流程及最新运行。主管可以核对审计记录。 |
| 规格与适配特征 | 下载「澄浦内衬必需适配特征_20261121.csv」并核对字段（含未测特征与指定打样组）。分析员可导入 UTF-8 CSV，保留数据指纹和原始行。 |
| 归并参数 | 选择批次和参数并提交后台计算，可从运行列表追踪状态与逐组核算进度。 |
| 归并与切树 | 查看业务指标、证据表、未测项补全结论和解释，通过来源链接回查数据。 |
| 打样复核 | 查看待处理或已完成记录。复核主管可提交打样复核及依据。 |
| 规格清单交付 | 按批查找结果，核对复核状态并下载相应的 CSV。 |

## 演示流程

1. 11 月 21 日 08:40，包装工程师将 14 份待归并规格整理到「澄浦内衬必需适配特征_20261121.csv」，其中 D/E/F 三个指定打样组含未测项（以问号结尾）。
2. 在「规格与适配特征」导入台账，核对 CP-A01 至 CP-F02 的规格编号、必需特征、未测特征和打样组编号。
3. 在「归并参数」将距离切线设为 0.40 并运行，查看切出的候选组与补全结论；运行中可在结果页看到逐组核算进度。
4. 在「归并与切树」追溯 CP-B03 的归并步骤，核对它与 CP-B01 的距离 0.60，以及两侧各自要求的特征。
5. 核对三个指定打样组：D 组无论怎么补都达标、E 组怎么补都超线、F 组只有部分补法达标，并查看各自的达标与超线补法示例。
6. 在「打样复核」记录定位孔和传感器让位的实物验证要求，签核后在「规格清单交付」导出。

## 计算口径

- 每条规格对应一组必需适配特征。用 | 分隔，去除特征首尾空白并按集合去重；特征名称按原有大小写匹配。
- 未测适配特征单独成列，同样用 | 分隔并以问号结尾（如 `定位孔?`）；未测项保留在台账中，每项可有可无。
- 指定打样组按台账中的打样组编号聚合，可跨切树候选组；未填写编号的规格沿用切树候选组参与补全核算。
- 两条规格的 Jaccard 距离为仅出现在一侧的特征数除以两侧特征并集数，取值为 0 至 1。
- 完全链接用两个组之间最远的规格对定义组间距离。每一步合并距离最小的组对，同距按两个组各自最小的规格编号折叠大小写后排序。
- 切树保留距离小于或等于切线的归并。结果列出每步最远规格对、两侧独有特征，以及超线最远的至多 50 个规格组合。
- 补全核算在冻结批次、组员与切线后进行：同一未测项的取值在组内各规格对共用，穷举全部补法，按分数精确比较切线，分为无论怎么补都达标、只有部分补法达标、怎么补都超线三类；能找到的达标和超线补法各举一例。
- 后台逐组核算并把检查点写入 `runs.progress`；进程中断后由租约重试机制从检查点继续，已完成的组不重复核算，站内回执按运行去重，重试不重复发布。单组未测变量超过 12 个时停止穷举并标记为 blocked。
- 候选组供实物打样复核，共有特征及各规格的独有要求应一并核对。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | MySQL 8 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
